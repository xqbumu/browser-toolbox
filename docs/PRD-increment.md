## 2. 逐项变更说明

### 2.1 依赖升级

**背景**：当前 `package.json` 已锁 `@wxt-dev/module-react@~1.1.5`，并通过 `overrides.@vitejs/plugin-react@4.4.1` 固定底层 React 插件版本，原因是较新的 `module-react` 会拉起要求 Vite 6 的 `@vitejs/plugin-react`，而当前 `wxt@0.19` + `vite@5.4` 组合只兼容 Vite 5。

**变更内容**：

| 包 | 当前版本 | 升级方向 |
| --- | --- | --- |
| `wxt` | `^0.19.0` | 升级到最新稳定版（若最新版已支持 Vite 6，则一并升级 Vite） |
| `vite` | `^5.4.8` | 随 WXT 版本要求升级（5 → 6） |
| `@wxt-dev/module-react` | `~1.1.5` | 升级到与新版 WXT/Vite 匹配的稳定版，评估解除锁定 |
| `@vitejs/plugin-react`（override） | `4.4.1` | 若升级 Vite 6，移除 override，由依赖树自动解析兼容版本 |
| `react` / `react-dom` | `^18.3.1` | 升级到 18 最新补丁版（本次不跨大版本到 19，避免无关风险） |
| `@types/react` / `@types/react-dom` | `^18.3.x` | 随 React 同步 |
| `typescript` | `^5.5.4` | 升级到 5.x 最新稳定版 |
| `jszip` | `^3.10.1` | 升级到 3.x 最新稳定版 |
| `vitest` | `^2.1.9` | 升级到最新稳定版 |

**决策（module-react 与 Vite 兼容性）**：

| 方案 | 动作 | 适用 |
| --- | --- | --- |
| **方案 A（推荐）** | `wxt` 升级到最新 → 若最新 WXT 要求 Vite 6，则同步升级 `vite@6`，`module-react` 升级到对应最新稳定版，**移除 `~1.1.5` 锁定与 `@vitejs/plugin-react` override**，让版本由依赖树解析 | 以「三目标构建 + 单测全绿」为准 |
| 方案 B（保守兜底） | 仅做 patch 级安全升级，维持 `vite@5` + `module-react@~1.1.5` + override 不变 | 方案 A 升级后出现构建/运行时回归时回退 |

**验收标准**：
- 升级后 `npm run build:chrome`、`npm run build:firefox`、`npm run build:safari` 三目标均构建通过。
- `npm test`（vitest）全绿，无类型错误（`npm run compile` 通过）。
- popup / options 在 Chrome、Firefox 下正常渲染、可交互，截图链路冒烟通过。
- 若采用方案 A，`package.json` 中 `overrides.@vitejs/plugin-react` 与 `@wxt-dev/module-react` 的 `~` 锁定应已移除或已升级到与 Vite 6 兼容的新版本。

### 2.2 默认保存目录配置（唯一可行方案）

**约束**：浏览器扩展**无法**通过 `downloads.download` 写入任意绝对路径，`filename` 只能以相对路径形式落在浏览器「下载」目录下。因此「保存目录」实际等价于「下载目录下的子文件夹名」。

**变更内容**：
- 新增配置项 `saveSubfolder`：截图文件保存到「下载」目录下的该子文件夹。
- 默认子文件夹名：**`网页截图`**（与产品名「网页截图助手」一致，用户可在设置里修改；留空 = 直接保存到下载根目录）。
- 下载时文件名由 `fileName` 变为 `saveSubfolder + '/' + fileName`（`saveSubfolder` 为空则不拼前缀）。
- 子文件夹名需清洗非法字符（复用 `naming.ts` 的非法字符集 `\/:*?"<>|` → `_`），并禁止 `.`、`..`、绝对路径、路径分隔符，防止越界。

**验收标准**：
- 设置 `saveSubfolder = "网页截图"` 后，截图下载到「下载/网页截图/域名_标题_时间戳.png」。
- 设置为空时，截图下载到「下载/域名_标题_时间戳.png」。
- 输入含 `/`、`..`、非法字符的值时被清洗或拒绝，不会导致路径越界或下载失败。
- 批量 Zip 同样落到该子文件夹（`saveSubfolder/screenshots_时间戳.zip`）。
- 子文件夹不存在时浏览器自动创建（`downloads.download` 原生行为，无需手动建目录）。

### 2.4 Popup UI 优化 + 历史截图列表

原 PRD 的 P2-1「截图历史管理」本次**提级为 P0 实现**，同时重构 popup 布局。

**功能需求（历史列表）**：

| 能力 | 说明 |
| --- | --- |
| 展示 | 最近截图列表，每项展示：缩略图、文件名、时间、来源 URL（域名） |
| 预览 | 点击缩略图/「预览」，在 popup 内弹层展示原图（可缩放，支持「在新标签页打开」） |
| 重新下载 | 用存储的原图重新触发 `downloads.download`，文件名与目录沿用当前保存配置 |
| 删除 | 单条删除；支持「清空历史」 |
| 上限 | 保留最近 N 条（默认 50），超限按最旧优先淘汰（LRU） |

**存储方案决策（重点厘清 ①）**：

| 方案 | 配额/容量 | 能否支撑「重新下载原图」 | 复杂度 | 结论 |
| --- | --- | --- | --- | --- |
| `storage.local` 仅存缩略图 + 元数据 | Chrome 默认 ~10MB | ❌ 无原图，只能预览缩略图 | 低 | 不满足需求 |
| `storage.local` 存原图 dataURL | ~10MB，单张长图 dataURL 可达数 MB，几十张即爆 | ⚠️ 部分（很快溢出） | 低 | ❌ 不推荐 |
| `storage.local` + `unlimitedStorage` 权限 | 容量提升但跨浏览器行为不一致、非硬保证 | ⚠️ 存原图 dataURL 体积大 | 中 | ❌ 不推荐 |
| **IndexedDB 存缩略图 + 原图 Blob + 元数据（推荐）** | 通常可达数百 MB ~ 数 GB | ✅ 是 | 中 | ✅ 推荐 |
| 混合：元数据存 `storage.local`、大图存 IndexedDB | 元数据小 + 大图走 IndexedDB | ✅ 是 | 高 | 可选，收益有限 |

**推荐结论**：历史记录**统一存 IndexedDB**（缩略图 + 原图 Blob + 元数据），配置仍走 `storage.sync`/`storage.local`（沿用现有 `utils/storage.ts`）。

理由：
1. `storage.local` 配额仅 ~10MB，长图单张原图（整页拼接可达数 MB 的 dataURL/Blob）几十条必然溢出，无法可靠支持「重新下载原图」。
2. IndexedDB 配额大（通常数百 MB 起）、在 MV3 Service Worker 中可用、Blob 存取高效、天然支持按 `createdAt` 建索引倒序查询。
3. 缩略图做降采样（最大边 ≤ 320px，JPEG/WebP 质量 0.7）以加速列表渲染、控制体积；原图 Blob 仅用于「预览/重新下载」时读取。

**容量权衡与淘汰策略**：
- 默认保留最近 50 条（`historyLimit`，可配置），超出按最旧优先删除。
- 单条存储估算：缩略图 ~10–50KB + 原图（视页面长度，几十 KB ~ 数 MB）。按 50 条、平均 1MB/条估算约 50MB 量级，IndexedDB 可承载。
- 删除条目时同步删除其缩略图与原图 Blob，避免孤儿数据。

**Popup UI 优化方向（重点厘清 ②，布局草案见 §4）**：
- 引入顶部 **Tab 分段控件**：「截图」/「历史」，把截图操作与历史浏览分屏，避免原单一纵向堆叠过长。
- 截图 Tab 内按「截图模式 → 开始截图（主按钮）→ 批量截图（可折叠）→ 状态/进度」的**层级分组**，主操作（整页截图）视觉上最突出。
- 历史 Tab 顶部提供搜索/清空，条目卡片化，操作按钮（预览/重新下载/删除）悬停或常驻显示。
- 统一视觉反馈：按钮 loading 态、成功/失败状态色、空状态占位（无历史时提示）、Safari 降级提示条保留。

**验收标准**：
- 每次截图成功后自动写入一条历史记录（含缩略图 + 原图 + 元数据）；批量截图按单条记录写入。
- 历史列表按时间倒序展示缩略图/文件名/时间/来源域名，数据正确。
- 「预览」能展示原图；「重新下载」能重新落盘到当前保存目录；「删除」能移除条目及其 Blob。
- 超过 `historyLimit` 后最旧条目被淘汰。
- popup 在 Chrome/Firefox 下布局正常，无横向溢出；Safari 降级提示仍生效。

## 4. UI 变更

### 4.1 Popup 布局草案（优化后）

```
┌──────────────────────────────────┐
│ 🖼️ 网页截图助手            ⚙️   │  ← 标题栏（右侧设置入口）
├──────────────────────────────────┤
│  [ 截图 ]   [ 历史 · 12 ]        │  ← 顶部 Tab 分段控件（历史带计数角标）
├──────────────────────────────────┤
│  ▲ 截图 Tab                      │
│  ┌─ 截图模式 ────────────────┐  │
│  │ ● 整页滚动截图（推荐）     │  │  ← 单选组，默认选中
│  │ ○ 可见区域                 │  │
│  │ ○ 选定区域                 │  │
│  └───────────────────────────┘  │
│  [ 📜 开始截图 ]  ← 主按钮（高亮）│
│  ┌─ 批量截图 ──（可折叠）───┐  │
│  │ [按选项卡批量] [按URL列表] │  │
│  └───────────────────────────┘  │
│  状态提示 / 进度条               │
├──────────────────────────────────┤
│  ▲ 历史 Tab                      │
│  [🔍 搜索]           [清空]     │
│  ┌────────────────────────────┐ │
│  │ ▦  example.com_首页_…      │ │  ← 缩略图 + 文件名（截断）
│  │   标题 · 2026-08-25 14:30  │ │  ← 时间
│  │   example.com              │ │  ← 来源域名
│  │   [预览] [重新下载] [删除] │ │  ← 操作按钮
│  └────────────────────────────┘ │
│  …（更多条目，按时间倒序）      │
│  （空状态：暂无截图记录）       │

```

交互要点：
- **Tab 切换**：「截图」「历史」互斥；历史 Tab 显示条目数角标。
- **视觉层级**：标题栏（品牌）→ Tab（导航）→ 分组卡片（截图模式 / 批量）→ 主按钮（最醒目）→ 状态/进度（次级）。
- **反馈**：截图进行中主按钮 loading；成功绿色、失败红色；批量进度条保留现有 `ProgressBar`。
- **历史条目**：缩略图居左，右侧三行（文件名 / 时间 / 域名）+ 操作按钮；预览为 popup 内弹层（原图等比缩放 + 「在新标签页打开」）。

### 4.2 Options 布局（新增「保存位置」「历史记录」分组）

```
┌──────────────────────────────────┐
│ ⚙️ 网页截图助手 · 设置           │
├──────────────────────────────────┤
│ 保存位置                        │
│  默认保存目录：[ 网页截图  ]     │  ← 子文件夹名（下载目录下）
│  说明：扩展只能写入浏览器「下载」│
│  目录，此处填写其下子文件夹名；  │
│  留空则直接存下载根目录。        │
│ 历史记录                        │
│  保留最近：[ 50 ] 条             │
├──────────────────────────────────┤
│ 截图参数（原有）                │
│  重叠区比例 / 网络空闲窗口 /     │
│  稳定延时 / 最大等待 / 输出格式  │
│ 高级（原有）                    │
│  处理固定元素 / 触发懒加载       │
│ [ 保存 ]  ✓ 已保存              │
└──────────────────────────────────┘
```

验收要点：`saveSubfolder` 保存后即时生效（下次下载即用新目录）；`historyLimit` 保存后即时生效；两者均写入 `storage.sync`（沿用现有读写与回退逻辑）。
